# Meta広告 制作・入稿・配信・運用マニュアル

- 文書ID: META-ADS-MANUAL-001
- 版: 1.0
- 作成日: 2026-09-04
- 用途: GPTによる企画・文章・画像制作、Claude Codeによる入稿下書き準備、Meta広告の検証・改善
- 正本: `CARSOL/meta-ads/`

## 1. 目的

Meta広告を次の再現可能なサイクルとして運用する。

1. 仮説を決める
2. GPTで広告コンセプト・文章・画像を作る
3. クリエイティブ品質をルールチェックする
4. Claude Codeで広告入稿用の下書き一式を生成・保存する
5. Meta広告マネージャで人が最終確認して公開する
6. 成果を広告単位で記録する
7. 勝ち筋・負け筋・顧客の反応をLearning Logへ蓄積する
8. 次回広告、LP、記事、SEOコンテンツへ再利用する

## 2. 広告開始前に必ず固定する項目

- 広告目的
- 対象者
- 商品・サービス
- 配信地域
- 配信期間
- 1日予算 / 総予算
- コンバージョン定義
- 主要KPI
- 比較対象となる既存広告
- 今回変える変数
- 今回変えない変数
- 遷移先または電話CTA
- 広告責任者 / 承認者

### A/Bテスト原則

1回のテストでは可能な限り1つの仮説だけを変える。たとえば電話CV、地域、配信設定、予算帯は固定し、クリエイティブと訴求だけを変更する。

## 3. クリエイティブ制作ルール

### 3.1 配置別素材

1つの画像を全配置へ自動適用しない。最低限以下を制作する。

| 用途 | 比率 | 推奨サイズ |
|---|---:|---:|
| Facebook / Instagramフィード | 4:5 | 1440×1800px（最低1080×1350） |
| Stories / Reels | 9:16 | 1440×2560px（最低1080×1920） |
| カルーセル / 正方形面 | 1:1 | 1080×1080px以上 |

必要に応じて横長1.91:1を追加する。余白を足して比率だけ合わせず、比率専用に再レイアウトする。

### 3.2 9:16セーフゾーン

重要な文字、ロゴ、顔、CTA、価格、日付、注意事項は以下へ置かない。

- 上部 約14%
- 下部 約35%
- 左右 約6%

1080×1920の場合の目安は上約270px、下約670px、左右各約65px。背景・写真・装飾は端まで伸ばしてよいが、読ませる情報は安全領域内に置く。

### 3.3 静止画

- 1画像1メッセージ
- 主要見出しは原則2行以内
- 補足は原則3行以内
- 画像内文章は最大3ブロックを基本
- スマホ縮小表示で主要見出しが読めること
- フォントは1素材2種類以内を基本
- 背景と文字のコントラストを十分に確保
- 四隅・上下端へ重要情報を置かない
- ロゴを過度に大きくしない
- Meta標準CTAと競合する疑似ボタンを置かない
- 長文は広告本文へ逃がす

### 3.4 動画

- 6〜30秒を社内標準
- 冒頭1〜3秒で対象者・課題・メリット・結論のいずれかを提示
- 音声OFFでも理解できる字幕または画面内テキスト
- CTAは最後に1つだけ
- Reels / Storiesは9:16安全領域を守る
- AI動画は崩れ始める前にカット
- 日本語音声は無理に長く喋らせず、必要なら字幕・後載せナレーションを利用

### 3.5 AI生成素材

最低限、使用ツール、制作日、元素材、主な編集内容、ロゴや人物の使用権を記録する。実在人物を本人の承諾なく推薦者のように見せない。

## 4. 広告文ルール

| 項目 | 基準 |
|---|---|
| メインテキスト | 60〜100文字程度を基本。必要時は長文化可 |
| 最重要メッセージ | 冒頭40文字以内 |
| 見出し | 15〜25文字程度 |
| CTA | 1種類 |
| ハッシュタグ | 0〜3個 |
| 絵文字 | 0〜3個 |

基本構造は「状況・テーマ → 提供価値 → 根拠・具体性 → 次の行動」。

### 避ける表現

- 根拠のない「絶対」「100%」「必ず」
- 根拠のないNo.1、唯一、日本一
- 実在しない締切・残席・割引
- 過度な恐怖・不安の煽り
- 個人属性を断定する表現
- 広告と実際のサービス条件の不一致
- 小さすぎる注記で重要条件を隠すこと
- 実際と異なる営業時間、定休日、支払時期、対応地域等

## 5. 事実確認ゲート

画像・本文・見出しを作る前に事業固有の事実を固定する。AIは固定事実にない内容を広告へ追加してはいけない。

特に、年中無休、即日支払い、全国対応、引取費用無料、専門店、No.1、実績件数、Google評価などは、根拠が確認されていない限り載せない。

## 6. GPTで広告を作る標準フロー

### STEP 1 Campaign Brief

GPTに以下を渡す。

- 固定事実
- 過去Learning Log
- 今回のCV
- 今回狙う顧客層
- 今回の仮説
- 既存勝ち広告
- 変更禁止事項

### STEP 2 コンセプト

画像を先に作らず、誰を狙うか、心理、主メッセージ、サブメッセージ、CTA、既存広告との違い、仮説、成功 / 失敗判定を文章で決める。

### STEP 3 コピー

最低限、画像内コピー、Primary Text、Headline、Description / 通話の説明、CTA、広告名を作る。

### STEP 4 画像

マスターコンセプト確定後、4:5、9:16、1:1を比率別に再構成する。必要なら1.91:1も作る。

### STEP 5 QA

- 事実誤認なし
- 日本語誤字なし
- ロゴ正しい
- 画像内主要メッセージ1つ
- 文字量過多でない
- 9:16安全領域OK
- CTA 1つ
- 配置別プレビュー想定OK
- 営業時間 / 定休日 / 支払時期等が正しい

## 7. Claude Codeで下書きまで作る

Claude CodeはMeta広告を勝手に公開しない。役割は「広告下書きパッケージの作成・検証・保存」まで。

推奨構成:

```text
CARSOL/meta-ads/
  campaigns/
    YYYY-MM-campaign/
      brief.md
      hypothesis.md
      copy.md
      image-spec.md
      assets/
        4x5/
        9x16/
        1x1/
      meta-draft.json
      qa.md
      results/
      learning.md
```

Claude Codeは事実照合、禁止表現、画像比率・解像度、9:16セーフゾーン、Primary Text / Headline / Description / CTA整形を行い、`meta-draft.json` と `qa.md` を生成する。BLOCKERがなければ `READY_FOR_META_DRAFT` とする。

Meta側の技術的自動化を行う場合も、最初はDraft作成までに限定し、公開は人間の承認後とする。

## 8. 命名規則

- キャンペーン: `META_[目的]_[地域]_[施策]_[YYYYMM]`
- 広告: `[訴求軸]_[形式]_[比率]_[版数]`
- 素材: `[施策名]_[訴求軸]_[形式]_[比率]_[版数]_[YYYYMMDD]`

「最終」「本当の最終」「修正版2」等は使わない。

## 9. 公開前チェック

Facebookフィード、Instagramフィード、Stories、Reelsで文字切れ、ロゴ切れ、CTA競合、URL / 電話番号、営業時間 / 定休日、CVイベント、予算、配信地域、広告名、版数を確認し最終承認する。

## 10. 配信後の分析単位

キャンペーン単位だけでなく広告単位で、消化金額、インプレッション、リーチ、結果数、CPA / CPL、CTR / クリック、品質ランキング、実通話、有効相談、他社相談状況、査定、成約、粗利益を記録する。

最終評価は `広告費 → 電話 → 有効相談 → 査定 → 買取成立 → 粗利益` まで接続して判断する。

## 11. Learning Log

テスト終了時に必ず、仮説、変更した変数、固定した変数、数値結果、顧客の質、勝ち筋、負け筋、新しい疑問、次回テスト、記事・LP・SEOへ転用できる顧客インサイトを記録する。

Learningは広告の反省文ではなく、次の広告・記事・LPを良くする一次データとして扱う。
