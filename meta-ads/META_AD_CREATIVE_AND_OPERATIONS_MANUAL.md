# Meta広告 制作・入稿・配信・運用マニュアル

- 文書ID: META-ADS-MANUAL-001
- 版: 1.0
- 作成日: 2026-09-04
- 用途: GPTによる企画・文章・画像制作、Claude Codeによる入稿下書き準備、Meta広告の検証・改善
- 位置づけ: 既存「Meta広告 制作・入稿・配信・運用ルール」を実務ワークフロー化した運用マニュアル

## 1. このマニュアルの目的

Meta広告を「思いつきで制作して配信する作業」ではなく、次の再現可能なサイクルとして運用する。

1. 仮説を決める
2. GPTで広告コンセプト・文章・画像を作る
3. クリエイティブ品質をルールチェックする
4. Claude Codeで広告入稿用の下書き一式を生成・保存する
5. Meta広告マネージャで人が最終確認して公開する
6. 成果を広告単位で記録する
7. 勝ち筋・負け筋・顧客の反応をLearning Logへ蓄積する
8. 次回広告、LP、記事、SEOコンテンツへ再利用する

---

## 2. 広告開始前に必ず決めること

広告を作る前に以下を固定する。

- 広告目的
- 対象者
- 商品・サービス
- 配信地域
- 配信期間
- 1日予算 / 総予算
- コンバージョン定義
- 主要KPI
- 比較対象となる既存広告
- 今回変える変数
- 今回変えない変数
- 遷移先または電話CTA
- 広告責任者 / 承認者

### A/Bテストの原則

1回のテストでは、できるだけ1つの仮説だけを変える。

例:

- 同じ電話CV
- 同じ地域
- 同じ配信設定
- 同じ予算帯
- クリエイティブと訴求だけ変更

こうすることで「客層が変わった原因」が広告メッセージなのか判定しやすくなる。

## 3. クリエイティブ制作ルール

### 3.1 配置別素材

1つの画像を全配置へ自動適用しない。

最低限、以下を制作する。

| 用途 | 比率 | 推奨サイズ |
|---|---:|---:|
| Facebook / Instagramフィード | 4:5 | 1440×1800px（最低1080×1350） |
| Stories / Reels | 9:16 | 1440×2560px（最低1080×1920） |
| カルーセル / 正方形面 | 1:1 | 1080×1080px以上 |

必要に応じて横長1.91:1を追加する。ただし余白を足して比率だけ合わせるのではなく、その比率専用に再レイアウトする。

### 3.2 9:16セーフゾーン

重要な文字、ロゴ、顔、CTA、価格、日付、注意事項は以下へ置かない。

- 上部 約14%
- 下部 約35%
- 左右 約6%

1080×1920の場合の目安:

- 上 約270px
- 下 約670px
- 左右 各約65px

背景・写真・装飾は端まで伸ばしてよいが、読ませる情報は安全領域内に置く。

### 3.3 静止画の原則

- 1画像1メッセージ
- 主要見出しは原則2行以内
- 補足は原則3行以内
- 画像内文章は最大3ブロックを基本
- スマホ縮小表示で主要見出しが読めること
- フォントは1素材2種類以内を基本
- 背景と文字のコントラストを十分に確保
- 四隅・上下端へ重要情報を置かない
- ロゴを過度に大きくしない
- Meta標準CTAと競合する疑似ボタンを置かない
- 長文は広告本文へ逃がす

### 3.4 動画の原則

- 6〜30秒を社内標準
- 冒頭1〜3秒で対象者・課題・メリット・結論のいずれかを提示
- 音声OFFでも理解できる字幕または画面内テキスト
- CTAは最後に1つだけ
- Reels / Storiesは9:16安全領域を守る
- AI動画は崩れ始める前にカットする
- 日本語音声は無理に長く喋らせず、必要なら字幕・後載せナレーションを利用

### 3.5 AI生成素材

AI生成画像・AI編集画像・AI動画を使用した場合は、最低限以下を記録する。

- 使用ツール
- 制作日
- 元素材
- 主な編集内容
- ロゴや人物の使用権
- 実在人物を本人の承諾なく推薦者のように見せていないか

## 4. 広告文ルール

### 社内推奨

| 項目 | 基準 |
|---|---|
| メインテキスト | 60〜100文字程度を基本。必要時は長文化可 |
| 最重要メッセージ | 冒頭40文字以内 |
| 見出し | 15〜25文字程度 |
| CTA | 1種類 |
| ハッシュタグ | 0〜3個 |
| 絵文字 | 0〜3個 |

### 基本構造

1. 状況・テーマ
2. 提供価値
3. 根拠・具体性
4. 次の行動

### 禁止 / 避ける表現

- 根拠のない「絶対」「100%」「必ず」
- 根拠のないNo.1、唯一、日本一
- 実在しない締切・残席・割引
- 過度な恐怖・不安の煽り
- 個人属性を断定する表現
- 広告と実際のサービス条件の不一致
- 小さすぎる注記で重要条件を隠すこと
- 実際と異なる営業時間、定休日、支払時期、対応地域等

## 5. 事実確認ゲート

画像・本文・見出しを作る前に、事業固有の事実を `facts.md` に固定する。

例:

```yaml
company: CARSOL
business: 中古車の買取・販売
campaign_service: 浸水車・動かない車の買取相談
payment: 即日支払いではない
closed_day: 水曜日
hours: 10:00-19:00
conversion: phone_call
```

AIは `facts.md` にない事実を広告へ追加してはいけない。

特に次はAIが勝手に補完しやすいため要注意。

- 年中無休
- 即日支払い
- 全国対応
- 引取費用無料
- 専門店
- No.1 / 実績件数 / Google評価

根拠が固定されていない限り広告へ載せない。

## 6. GPTで広告を作る標準フロー

### STEP 1: Campaign Brief

GPTに以下を渡す。

- `facts.md`
- 過去Learning Log
- 今回のCV
- 今回狙う顧客層
- 今回の仮説
- 既存勝ち広告
- 変更禁止事項

### STEP 2: コンセプト生成

GPTは先に画像を作らず、次を文章で出す。

- 誰を狙うか
- どんな心理を狙うか
- 主メッセージ
- サブメッセージ
- CTA
- 既存広告との違い
- 仮説
- 成功 / 失敗の判定方法

### STEP 3: コピー生成

最低限以下を作成する。

- 画像内コピー
- Metaメインテキスト
- 見出し
- 通話の説明 / 説明文
- CTA
- 広告名

### STEP 4: 画像生成

最初に1案のマスターコンセプトを確定し、その後比率ごとに再構成する。

最低セット:

- 4:5
- 9:16
- 1:1

必要なら1.91:1。

### STEP 5: QA

チェック項目:

- 事実誤認なし
- 日本語誤字なし
- ロゴ正しい
- 画像内主要メッセージ1つ
- 文字量過多でない
- 9:16安全領域OK
- CTA 1つ
- 配置別プレビュー想定OK
- 営業時間 / 定休日 / 支払時期等が正しい

## 7. Claude Codeで下書きまで作る標準フロー

Claude CodeはMeta広告を勝手に公開しない。

役割は「広告下書きパッケージの作成・検証・保存」までとする。

### 推奨ディレクトリ

```text
meta-ads/
  manual/
  brands/
    cars​​ol/
      facts.md
      brand.md
  campaigns/
    2026-09-carsol-flooded-car/
      brief.md
      hypothesis.md
      copy.md
      assets/
        4x5/
        9x16/
        1x1/
      meta-draft.json
      qa.md
      results/
      learning.md
```

### Claude Codeの処理

1. facts / brief / learningを読む
2. 必須ファイルの有無を確認
3. 画像サイズを検証
4. 禁止語・事実条件を検証
5. Meta入稿項目を `meta-draft.json` にまとめる
6. `qa.md` にPASS / BLOCKERを出す
7. BLOCKERがなければ `READY_FOR_META_DRAFT` とする
8. 人がMeta広告マネージャで最終入稿・プレビュー・公開

### meta-draft.json例

```json
{
  "campaign_goal": "phone_call",
  "creative_angle": "hassle_free_fast_response",
  "primary_text": "...",
  "headline": "...",
  "call_description": "...",
  "cta": "CALL_NOW",
  "assets": {
    "feed_4x5": "assets/4x5/v01.png",
    "stories_reels_9x16": "assets/9x16/v01.png",
    "square_1x1": "assets/1x1/v01.png"
  },
  "status": "READY_FOR_META_DRAFT"
}
```

Meta側のAPI・ブラウザ操作を自動化する場合も、最初は「下書き保存のみ」に限定し、公開は人間の承認後とする。

## 10. 配信後の分析単位

キャンペーン単位だけではなく、広告単位で最低限記録する。

- 消化金額
- インプレッション
- リーチ
- 結果数
- CPA / CPL
- CTR / クリック（取得できる場合）
- 品質ランキング
- 実通話
- 有効相談
- 他社相談状況
- 査定
- 成約
- 粗利益

### 最終評価

Meta上のCPAだけでは勝ち広告と断定しない。

`広告費 -> 電話 -> 有効相談 -> 査定 -> 買取成立 -> 粗利益`

まで接続して判断する。

## 11. Learning Logルール

広告テスト終了時に必ず以下を記録する。

- 仮説
- 変更した変数
- 変更しなかった変数
- 数値結果
- 顧客の質
- 勝ち筋
- 負け筋
- 新しい疑問
- 次回テスト
- 記事・LP・SEOへ転用できる顧客インサイト

Learningは「広告の反省文」ではなく、次の広告・記事・LPを良くする一次データとして扱う。
